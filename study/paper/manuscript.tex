\begin{abstract}
Question-answering assistants for software libraries retrieve documentation before they answer, but
documentation exists in many versions, and a retriever that ignores versions can return a page that was
correct for an older release. We measure how often this happens, using real documentation snapshots of
FastAPI, pandas, scikit-learn and Pydantic taken at two release tags each (\NSections{} sections, \NPairs{}
sections present in both versions), three classical retrievers (BM25, TF-IDF, LSA), and no language model.
On the \NChanged{} sections whose text changed materially between releases, a version-blind retriever returned the
\emph{other, different} version as its top result for \StaleHMin--\StaleHMax\% of queries phrased as a section
heading. Filtering candidates by the requested version removed these errors (by construction) and raised top-1
accuracy from \HitBlindHMin--\HitBlindHMax\% to \HitAwareHMin--\HitAwareHMax\%. Separately, we test whether the
top retrieval score can be used to refuse out-of-corpus questions: with a threshold learned on other libraries, it
reached an F1 of \CFscore\% (AUROC \CauROC) on held-out libraries. The study is small and uses synthetic queries, so we
treat it as a measurement of a failure mode, not as a benchmark of question-answering systems. Code, data
snapshots and all results are released and regenerate with one command.
\end{abstract}

\section{Introduction}
Developers now routinely ask assistants how to use a library, and most such assistants answer from retrieved
documentation. Retrieval-augmented generation (RAG)~\cite{lewis2020rag} improves grounding, but it inherits every
weakness of the retriever. One weakness is specific to software: documentation is versioned. A pandas page on inferring datetime formats and a Pydantic page on parsing data into a specified type
each exist in two releases whose texts differ (Appendix~\ref{app:ex}). If the retriever ranks by lexical or semantic similarity alone, two
versions of the same page look almost identical, and the choice between them is close to arbitrary.

This is the retrieval half of a larger reliability problem. Language models that are handed stale or conflicting
text tend to repeat it~\cite{xu2024conflicts,ji2023hallucination}, and they tend to answer even when the retrieved text does
not contain the answer~\cite{chen2024rgb}. Before studying whole question-answering systems, which involve language models,
prompts and judges, it is worth knowing how large the problem already is at the retrieval step. That is
cheap to measure and fully deterministic, and it is what this paper does.

We ask three concrete questions.
\begin{description}\setlength{\itemsep}{1pt}
\item[RQ1 (outdated documents).] How often does a version-blind retriever return the wrong version of a section, and how much does
filtering by the requested version help?
\item[RQ2 (conflicting sources).] When it returns the wrong version, how often is that version materially different from
the right one, so that a user would receive different information?
\item[RQ3 (insufficient evidence).] Can the top retrieval score alone be used to decide that the corpus does not contain an answer?
\end{description}

\paragraph{Contributions.} (i) A version-paired section corpus built from real release tags of four widely used
libraries, with a transparent definition of ``changed'' and ``unchanged'' sections. (ii) A measurement of version
confusion for three classical retrievers, with metrics that separate harmless from harmful confusion. (iii) A
leave-one-library-out test of score-based abstention. (iv) A fully reproducible pipeline that needs no external
service.

\section{Related Work}
\paragraph{Retrieval for question answering.}
RAG pairs a retriever with a generator~\cite{lewis2020rag}. The retriever may be sparse, such as TF-IDF~\cite{salton1988tfidf} and
BM25~\cite{robertson2009bm25}, latent, such as LSA~\cite{deerwester1990lsa}, or a trained dense model~\cite{karpukhin2020dpr}; surveys
cover the many variants~\cite{gao2023ragsurvey}. We use the three classical retrievers because they are deterministic, run without
network access and make no use of a language model, which keeps the study fully reproducible. This also means our
findings concern lexical and latent similarity and may not transfer to trained dense retrievers.

\paragraph{Robustness and conflicts.}
Benchmarks for RAG test robustness to noisy retrieved text and the ability to decline when evidence is missing~\cite{chen2024rgb}, and a
body of work studies how models behave when retrieved context conflicts with itself or with what they memorised~\cite{xu2024conflicts}.
Our RQ2 and RQ3 correspond to those two concerns, but we measure them at the retrieval layer on versioned software documentation,
where a conflict has a precise cause: two releases of the same page.

\paragraph{Sections.}
Each file is split at its headings (Markdown \texttt{\#} headings, reStructuredText underlined titles). Code blocks, directives, links and
inline markup are stripped, and a section keeps at most 400 words. Release notes, changelogs and similar files are skipped.

\paragraph{Pairing across versions.}
A section of the old release is paired with a section of the new release when their normalised headings are identical and
unique within each version, the heading is not generic (``Example'', ``Introduction'', \dots) and has at least six characters. This gives
\NPairs{} pairs. We classify each pair by the Jaccard similarity $J$ of the two texts' word sets: \emph{unchanged} if $J\ge0.95$ (\NUnchanged{} pairs),
\emph{changed} if $J<0.80$ (\NChanged{} pairs, meaning at least a fifth of the vocabulary differs), and \emph{partial} otherwise (\NPartial{} pairs,
excluded from the main experiments). Figure~\ref{fig:comp} shows the composition. ``Changed'' is a lexical notion: it does not tell us whether a change
is an API change or a rewording, a point we return to in Section~\ref{sec:limits}.

\section{Methods}
\paragraph{Retrievers.}
Retrieval is done within one library at a time, over the sections of \emph{both} releases, which mirrors a user asking about one
library. The text indexed for a section is its heading plus its body. We use \textbf{BM25} ($k_1=1.5$, $b=0.75$), \textbf{TF-IDF} (sublinear term
frequency, cosine similarity) and \textbf{LSA} (TF-IDF followed by a 100-dimensional truncated SVD). All three use English stop-word removal.
When two candidates tie exactly, which happens for identical sections, the tie is broken at random with a fixed seed; a deterministic rule would silently favour one version.

\paragraph{Version-blind and version-aware modes.}
In \emph{blind} mode the ranking is over all sections of the library. In \emph{aware} mode the candidate set is restricted to the requested version,
which models an assistant that knows the user's release. The query is identical in both modes.

\paragraph{Queries.}
For every paired section we create two queries, one targeting the old and one the new release, so a pair yields two queries with opposite
correct versions. Two query styles are used: \emph{heading} (the section heading alone, as a user might phrase a topic) and \emph{heading+sentence} (the heading
followed by the section's first sentence in the target version, which leaks some version-specific wording). The target section is the section with that heading in the requested version.

\paragraph{Metrics (RQ1, RQ2).}
\emph{Hit@1}: the top result is exactly the target section. \emph{Equivalent Hit@1}: the top result is the target section or a section whose text is
at least 0.95 Jaccard-similar to it, so that the user would receive the same information. \emph{Stale@1}: the top result is the other version's section \emph{and} the pair is in
the changed class; it counts only harmful version confusion. We also report Recall@5 and mean reciprocal rank (MRR). Confidence intervals are 95\% percentile
bootstraps over queries~\cite{efron1979}. Blind and aware modes are compared with the exact McNemar test~\cite{mcnemar1947}, which we report for completeness, though
the outcome is close to guaranteed by construction (Section~\ref{sec:res-a}).

\paragraph{Abstention (RQ3).}
The index holds the new-release sections of the libraries not held out. \emph{Answerable} queries are the heading and first sentence of an \emph{old}-release section whose paired section exists in the index
(a question phrased from older documentation, answered by newer documentation). \emph{Unanswerable} queries are built the same way from a held-out library. The score is the top-1 TF-IDF cosine
similarity; the system abstains when it falls below a threshold. In each leave-one-library-out fold $h$ the threshold is chosen to maximise the F1 of the abstain class
on development data built from the \emph{other} libraries (each one in turn playing the unanswerable library against an index that excludes $h$ and it), and is then applied unchanged to fold $h$. We
report precision, recall and F1 of abstention, the share of answerable queries still answered, and AUROC. Each fold uses 150 answerable and 150 unanswerable queries (sampled with a fixed seed).

\paragraph{Reproducibility.}
Everything is deterministic (seed 0), runs on a laptop CPU in about a minute, and needs no network access once the snapshots are present.

\section{Results}
\label{sec:results}
\subsection{Version confusion in blind retrieval (RQ1, RQ2)}
\label{sec:res-a}
Table~\ref{tab:ab} and Figure~\ref{fig:hit} summarise \NQueriesChanged{} queries over the \NChanged{} changed sections. With heading queries, a version-blind retriever returned the exact target
section at the top for only \HitBlindHMin--\HitBlindHMax\% of queries, and returned the \emph{other}, materially different version for \StaleHMin--\StaleHMax\%. This is close to what the design implies: the two
queries of a pair are identical text, so a blind ranking cannot depend on the requested version, and at most one of the two can be right. Adding the target version's first sentence helped
(Hit@1 \HitBlindFMin--\HitBlindFMax\%) but did not solve the problem: stale hits stayed at \StaleFMin--\StaleFMax\%, because a changed section still shares most of its vocabulary with its predecessor.

Restricting candidates to the requested version eliminated stale hits entirely and raised Hit@1 to \HitAwareHMin--\HitAwareHMax\% (heading) and \HitAwareFMin--\HitAwareFMax\% (heading+sentence). Recall@5 on heading queries
rose from \RecBlindMin--\RecBlindMax\% to \RecAwareMin--\RecAwareMax\%. The exact McNemar test favours aware mode for every retriever and query style (Appendix Table~\ref{tab:mc}), but the comparison is nearly tautological: aware
mode searches a subset of the candidates that blind mode searches, so there is no query on which it can lose the correct section to the other version. We report it only for completeness.
The remaining errors in aware mode are not version errors but ordinary retrieval errors, such as a different section with a similar heading; BM25 was best, TF-IDF second and LSA clearly worst, which is
plausible for short, vocabulary-specific technical text and a small 100-dimensional latent space.

\paragraph{Harmless versus harmful confusion.}
Among the \NUnchanged{} unchanged sections (Appendix Table~\ref{tab:unch}), a blind retriever returned the other version for \UWrongMin--\UWrongMax\% of queries, yet this was harmless: the two versions have the same
text. Strict Hit@1 therefore understates blind performance (\UStrMin--\UStrMax\%), and Equivalent Hit@1 (\UEqMin--\UEqMax\%) is the right measure there. The practical lesson is that ``wrong version'' is not
itself the error to count; wrong version \emph{with different content} is. This is why we separate Stale@1 from Hit@1.

\paragraph{Differences between libraries and thresholds.}
Stale rates for heading queries ranged from \LibStaleMin\% to \LibStaleMax\% across library--retriever pairs (Figure~\ref{fig:lib}); Pydantic, whose releases span a major rewrite, was highest for each retriever, but with
33--61 changed sections per library these differences are small compared with the intervals and we do not interpret the ranking. The headline result was insensitive to how ``changed'' is defined: BM25 stale rates were \SensMin--\SensMax\%
for cut-offs of 0.6, 0.7 and 0.8 ($n\ge\SensNLow$ queries).

\subsection{Abstention from the retrieval score (RQ3)}
Table~\ref{tab:c} and Figure~\ref{fig:abs} give the leave-one-library-out results over \CN{} queries. Pooled over folds, the score-based rule reached an abstention precision of \CPrec\% and recall of \CRec\% (F1 \CFscore\%, AUROC \CauROC) while still answering
\CKept\% of the answerable queries. Per held-out library, F1 ranged from \FoldLowF\% (\FoldLowName) to \FoldHighF\% (\FoldHighName) and AUROC from \FoldLowAU{} to \FoldHighAU. The thresholds learned on other libraries transferred well, which suggests that a single score cut-off may be a usable first
line of defence against out-of-corpus questions. The weakest fold was \FoldLowName; we did not investigate why.

\section{Discussion}
Three points stand out. First, version blindness is a large, easily measured and easily fixed retrieval failure: about a third to two fifths of top results, for queries that name a topic but not wording unique to one release, were the right page
from the wrong release, with different content. Filtering by version is cheap, but it requires that the assistant \emph{knows} the user's version and that every document carries version metadata; in practice
both are often missing, so the cost of the fix is in the metadata pipeline, not in the retriever. Second, the metric matters. Counting all wrong-version hits would suggest a blind retriever fails about half the time on unchanged pages; counting only hits whose content differs gives
the number that affects users. Third, a refusal rule based on a single similarity score is surprisingly effective for out-of-corpus questions, but the unanswerable questions here come from a different library and are therefore easy; the harder case, a question about the right library that the documentation does not cover, is untested.

For the broader goal of reliable question answering with language models, these results suggest an ordering of effort. Version-aware candidate selection and a calibrated refusal threshold are inexpensive steps that precede, and may reduce the need for, more elaborate
verification or multi-agent machinery. We emphasise \emph{may}: we did not measure any language model here, and whether the retrieval-level gains carry through to answer-level correctness is the natural next study.

\section{Limitations}
\label{sec:limits}
\begin{itemize}\setlength{\itemsep}{1pt}
\item \textbf{Synthetic queries.} Queries are built from section headings and first sentences, not from real user questions. Real questions are longer and more varied, and may be easier or harder.
\item \textbf{Section-level relevance.} The target is a single section, whereas many questions could be answered by several. Hit@1 therefore understates real usefulness, and aware-mode errors include reasonable alternatives.
\item \textbf{Lexical change.} ``Changed'' means a word-set difference. It does not separate API changes from rewordings, so some changed pairs are cosmetic, and some meaningful one-line changes (a renamed parameter) fall in the unchanged or partial classes.
\item \textbf{Pairing by heading.} Sections that were renamed, merged or moved are not paired, and a coincidentally shared heading could pair unrelated text. Generic headings are excluded, which reduces but does not remove the second risk.
\item \textbf{Classical retrievers.} We did not evaluate trained dense retrievers, because the study is designed to run without model downloads or services. Dense models may separate versions differently.
\item \textbf{Easy abstention task.} The unanswerable queries come from another library, and some may be partly answerable from topically similar sections of the indexed libraries, which would count as errors against the rule.
\item \textbf{Scale.} Four libraries, two releases each, and 197 changed sections; per-library differences are not statistically reliable.
\item \textbf{No language model.} Nothing here shows what a generator does with stale or refused context.
\end{itemize}

\section{Reproducibility}
The repository contains the documentation snapshots (Markdown and reStructuredText only, with the upstream licences retained; see \texttt{data/NOTICE.md}), the parser (\texttt{scripts/}\allowbreak\texttt{build\_sections.py}),
the study (\texttt{experiments/}\allowbreak\texttt{run\_study.py}) and the paper source. Running the two scripts in order (\texttt{build\_sections.py}, then \texttt{run\_study.py}) regenerates every table, figure and number in the prose (via \texttt{results/macros.tex});
\texttt{scripts/fetch\_docs.sh} re-downloads the snapshots at the pinned tags. Per-query results are saved in \texttt{results/}\allowbreak\texttt{exp\_ab\_per\_query.csv.gz} so every aggregate can be re-derived. All figures in this paper are produced by the same script and are also shown in the repository's README.

\section{Conclusion}
On real, versioned documentation, a version-blind retriever returns a materially different version of the right page for a third to two fifths of topic-style queries, and a version filter removes that failure and lifts top-1 accuracy substantially. A single retrieval-score threshold
learned on other libraries can refuse most out-of-corpus questions while still answering nearly all in-corpus ones. The conclusions are limited by synthetic queries and classical retrievers, but the measurement is cheap, deterministic and reproducible, and it gives a concrete baseline against which language-model pipelines can later be compared.

\section{Processing details}
Headings in Markdown are lines beginning with one to four \texttt{\#} characters outside fenced code blocks, with trailing anchor attributes removed. In reStructuredText a heading is a non-indented text line followed by a line
of a repeated punctuation character at least as long as the title minus one. Text is cleaned by removing fenced code, directives, images, link targets, inline markup characters and HTML-like tags; whitespace is collapsed. Sections under 30 words are
dropped, and sections longer than 400 words are truncated. Files whose names contain release, changelog, history, whatsnew, contributing, sponsor, external-links, newsletter or help are skipped. Normalised headings are lower-cased alphanumeric word sequences.
Generic headings excluded from pairing: introduction, example(s), recap, check it, install(ation), summary, conclusion, usage, overview, note(s), see also, references, tip, warning, alternatives, technical details, in short, review, next steps, intro, background, limitations.
